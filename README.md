# Kapture Finance Voicebot (Maya)

## 📌 Project Overview
Maya is an outbound collections voicebot for **Kapture Finance**.  
It verifies customers, discloses overdue EMI amounts only after authentication, and helps resolve payments by logging promises or sending payment links.  
The backend is built with **FastAPI**, exposed via **ngrok**, and connected to **Vapi.ai** for voice orchestration.

---

## ⚙️ Installation & Setup (Step by Step)

### 1. Install Python and dependencies
Make sure you have Python 3.10+ installed. Then run:
```bash
pip install fastapi uvicorn pydantic
```
Clone repository and install dependencies:

bash
pip install fastapi uvicorn pydantic

### 2. Run the FastAPI server
Start the backend server locally:
```bash
uvicorn src.server:app --reload --port 8000
```

### 3. Expose server with ngrok
Since Vapi needs a public URL, expose your local server:
```bash
ngrok http 8000
```
Copy the HTTPS URL generated by ngrok.

### 4. Configure Vapi assistant
- Go to [Vapi.ai](https://vapi.ai) and create a new assistant.
- Choose:
  - **Model**: `gpt-4.1`
  - **Voice**: e.g., `Elliot`
  - **Transcriber**: `soniox`
- Add tool endpoints using your ngrok URL:
  - `/verify_customer`
  - `/log_promise_to_pay`
  - `/send_payment_link`

### 5. Test endpoints
Use `curl` or Postman to confirm responses:

```bash
curl -X POST https://<ngrok-url>/verify_customer \
  -H "Content-Type: application/json" \
  -d '{"dob":"15/03/2005","pan_last4":"ABCD","customer_id":""}'
```

Expected response:
```json
{"verified": true, "customer": {"dob":"15/03/2005","pan_last4":"ABCD","customer_id":""}}
```

---

🛠️ Tools Implemented
verify_customer  
Input: customer_id, dob, pan_last4  
Output: {"verified": True/False}  
Ensures identity is confirmed before any debt disclosure.

log_promise_to_pay  
Input: customer_id, amount, date  
Output: {"logged": True/False}  
Records customer’s payment commitment.

send_payment_link  
Input: customer_id, link  
Output: {"sent": True/False}  
Sends a payment link to the customer.

---
Design Choices
State machine enforcement: Authentication is locked before debt disclosure.

Dynamic verification: Accepts either customer_id or DOB+PAN, avoiding hardcoded checks.

Boolean flags: Responses (verified, logged, sent) align with Vapi’s schema for smooth orchestration.

Guardrails: Do‑not‑call, wrong number, already‑paid handled gracefully.

Observability: Logging raw JSON payloads for debugging; metrics like containment rate and PTP rate can be tracked.
Debugging Notes
Initial errors: 422 Unprocessable Content due to schema mismatch.

Fix: Made all fields optional in Pydantic models and aligned response format with Vapi’s expectations.

Issue: customer_id often empty → verification failed.

Fix: Dynamic logic using DOB+PAN as alternative verification.

Verified with live calls: /verify_customer, /log_promise_to_pay, /send_payment_link all return 200 OK.

## 🏗️ Architecture Description
**Pipeline**:  
Telephony (Vapi outbound call) → Speech‑to‑Text (Soniox STT) → Orchestrator (LLM, GPT‑4.1) → FastAPI tools → Text‑to‑Speech (Elliot voice) → Customer.

**Latency budget per hop**:  
- STT: ~300ms  
- LLM response: ~1–2s  
- Tool call: ~200–400ms  
- TTS: ~300ms  
- End‑to‑end: target <3s per turn.
